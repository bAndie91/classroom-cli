About this application

What is classroom-cli?

classroom-cli is a personal, open-source command-line application that lets the developer and a small circle of explicitly invited family members read their Google Classroom course listings, announcements, coursework, materials, topics, rosters, and student submissions — conveniently all from the terminal.

The application is not a commercial product and is not offered to the general public. Access to the Google Cloud project is restricted to the developer and a handful of trusted test users who were individually and personally invited and accepted.

$ classroom-cli announcements --course "Math 9B"
[2024-11-14] Homework due Friday — chapters 4–6
[2024-11-12] Midterm results posted
[2024-11-08] No class on Monday (national holiday)
3 announcements · course id: 12345678

How it works

The user launches classroom-cli manually from their own machine. The tool authenticates once via Google's OAuth 2.0 flow and stores the resulting token locally. Subsequent runs use the stored token to call Google Classroom APIs on the user's behalf, print the requested information to the terminal, and exit. No server, no cloud backend, no database.

User control & data flow

classroom-cli always operates in a user-initiated and user-controlled manner. It runs exclusively on the user's local machine. It does not transmit, forward, store remotely, aggregate, or share any Google user data with any third party, server, analytics service, or communication channel. The only network calls it ever makes are directly to Google's own APIs on behalf of the authenticated user.

Intended audience

This application is intended solely for its developer and those few family members with whom the developer has personally agreed on the conditions of use. It is not distributed publicly, not listed in any app store, and not marketed to anyone else.

Permissions & data access

classroom-cli requests the minimum set of Google API scopes necessary to read classroom data on behalf of the authenticated user. All scopes are read-only. The application never writes, modifies, or deletes any data in Google Classroom or Google Drive.

Scope What it allows Access
classroom.courses.readonly List courses the user is enrolled in read-only
classroom.course-work.readonly Read assignments and coursework items read-only
classroom.courseworkmaterials.readonly Read course material posts read-only
classroom.student-submissions.me.readonly Read the user's own submission status and grades read-only
classroom.announcements.readonly Read teacher announcements in enrolled courses read-only
classroom.rosters.readonly Read course membership lists read-only
classroom.topics.readonly Read topic labels within courses read-only
drive.readonly Read Drive files that are attached to classroom posts (e.g. linked documents, PDFs). Used solely to retrieve file metadata and content for display in the terminal. read-only
Why drive.readonly?

Google Drive files – documents, slides, PDFs – are frequently attached to Classroom announcements and coursework. The drive.readonly scope allows classroom-cli to fetch those attachments so the user can read their content inline in the terminal. The tool never downloads files to any location other than temporary memory, never modifies Drive files, and never shares file contents with anyone other than the user who initiated the command.

1. Identity of the data controller

classroom-cli is a personal software project developed and maintained by its sole author (hereafter "the developer"). It is not operated by a company or organisation. The developer can be reached at the contact address associated with the Google Cloud project that hosts this application.

2. Scope of this policy

This policy applies to all persons who authenticate with classroom-cli through Google OAuth 2.0, including the developer and the small number of invited family members who have been personally and explicitly granted access to the Google Cloud project.

3. Google user data accessed

When you authorise classroom-cli, it obtains an OAuth 2.0 access token and refresh token from Google. Using this token it accesses the Google Classroom API and, where classroom posts contain Drive attachments, the Google Drive API — strictly on your behalf and strictly to fulfil the display request you issued.

The categories of data accessed are: course names and metadata, announcements, coursework assignments, course materials, topic labels, course rosters, your own submission statuses, and the content of Drive files linked within those classroom items.

4. How we use Google user data

Google user data obtained through the scopes listed above is used for exactly one purpose: to format and display the requested information in the terminal window of the user who issued the command. No other use is made of this data.

5. Data storage and retention

OAuth tokens are stored in a local file on the user's own machine (typically under their home directory). No other Google user data is written to disk by classroom-cli; data fetched from the API is held in process memory only for the duration of the command and discarded immediately upon exit.

The developer does not have access to any OAuth tokens belonging to other users, nor to any Google user data retrieved by their runs of the tool.

6. Data sharing and transmission

classroom-cli does not share, sell, rent, transmit, forward, upload, or in any other way communicate Google user data to any third party, server, analytics service, database, cloud backend, or communication channel — whether open or hidden.
